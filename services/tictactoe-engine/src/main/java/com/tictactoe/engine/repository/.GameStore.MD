# GameStore

The repository-facing service that `GameService` talks to instead of touching JPA directly. It exposes exactly the touchpoints `applyMove` and friends need — `load`, `create`, and `compareAndSave` — so `GameService` never sees `GameEntity`, `GameJpaRepository`, or `UUID`. `compareAndSave` writes the new board only if the stored board still equals the one the `Game` was loaded with (a single conditional `UPDATE`), so it needs no locking and no second `findById`.

## Key Components

- `@Component` - Registers this as a Spring bean, the sole collaborator `GameService` needs for persistence.
- `GameStore(GameJpaRepository gameRepository)` - Constructor injection of the JPA repository.
- `load(String gameId)` - Fetches the `GameEntity` by id (via `toUuid`), throwing `GameNotFoundException` if absent, and wraps it in a `Game`.
- `create(String gameId, List<String> board)` - Builds a new `GameEntity` with `GameState.IN_PROGRESS` and the given board, and saves it.
- `compareAndSave(Game game, List<String> board, GameState state)` - Issues `GameJpaRepository.compareAndSwapBoard` with `game.rawBoard()` as the expected value; returns `true` when exactly one row was updated (this call won the race) and `false` when another writer changed the board first, leaving the caller to re-read and re-validate.
- `toUuid(String gameId)` - Parses a game id string into a `UUID`, throwing `BadRequestException` with `ErrorCode.INVALID_GAME_ID` (→ 400) for a malformed id.

## Usage Example

```java
Game game = gameStore.load(gameId);
List<String> board = new ArrayList<>(game.board());
board.set(position, symbol.name());
boolean won = gameStore.compareAndSave(game, board, GameState.X_WON);
```

`GameService.applyMove` loads the game, computes the new board and outcome, then calls `compareAndSave` with the same `Game` instance. A `false` return means another move landed first; `applyMove` loops, re-reading and re-validating rather than blindly retrying the write — see `docs/adr/0003-optimistic-concurrency-on-moves.md`.
