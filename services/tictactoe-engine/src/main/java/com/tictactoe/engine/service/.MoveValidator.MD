# MoveValidator

Validates a move against the current board and game state, producing the `StepStatus` that `GameService` reports back on rejection. Precedence among the checks is deliberately last-rule-wins — the reverse of the reading order in the method body: `OUT_OF_TURN` > `CELL_OCCUPIED` > `INVALID_POSITION` > `INVALID_SYMBOL` > `GAME_FINISHED`. This must stay as sequential overwrites of a single `status` variable rather than early returns, because several rules can match the same request at once (e.g. a finished game with an occupied cell must report `CELL_OCCUPIED`, not `GAME_FINISHED`), and converting to early returns would silently change which status wins.

## Key Components

- `@Component` - Registers this as a Spring bean, injected into `GameService`.
- `MoveValidator(TurnPolicy turnPolicy)` - Constructor injection of the turn-order collaborator.
- `validate(List<String> board, GameState state, MoveRequest move)` - Runs all five rejection checks in sequence, letting later checks overwrite the status set by earlier ones, and returns `StepStatus.CORRECT_STEP` if none matched. Checks, in written order: game already finished, symbol missing, position out of `0..8` range, cell occupied, out-of-turn move (via `TurnPolicy.isOutOfTurn`).

## Usage Example

```java
StepStatus status = moveValidator.validate(board, game.state(), move);
if (status != StepStatus.CORRECT_STEP) {
    return new MoveResponse(board, game.state(), status, null);
}
```

`GameService.applyMove` calls `validate` before mutating the board; any non-`CORRECT_STEP` result short-circuits the move with the unchanged board and no persistence.
