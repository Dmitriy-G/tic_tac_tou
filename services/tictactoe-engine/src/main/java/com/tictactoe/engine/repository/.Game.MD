# Game

A loaded game, opaque to callers outside the `repository` package. Wraps the JPA `GameEntity` so `GameStore.compareAndSave` can reuse the exact row a prior `GameStore.load` already fetched, and so it has the exact stored board string to use as the compare-and-swap predicate. This is the boundary type that lets `GameService` work with plain `List<String>` boards and the `GameState` enum without ever seeing `GameEntity`, `GameJpaRepository`, or `UUID`.

## Key Components

- `entity` - The wrapped `GameEntity`, package-private and immutable from outside `repository`.
- `Game(GameEntity entity)` - Package-private constructor; only `GameStore` can create instances.
- `board()` - Returns the board as `List<String>`, converted from the entity's 9-character string via `BoardUtils.convertToList`.
- `state()` - Returns the entity's `GameState`.
- `entity()` - Package-private accessor exposing the underlying `GameEntity` so `GameStore.compareAndSave` can read its id and persist the same row without a redundant read.
- `rawBoard()` - Package-private accessor returning the entity's exact stored board string, used as the `expectedBoard` compare-and-swap predicate in `GameStore.compareAndSave`. Deliberately not `BoardUtils.convertToString(game.board())` — that happens to round-trip today, but tying correctness to it would be fragile.

## Usage Example

```java
Game game = gameStore.load(gameId);
List<String> board = new ArrayList<>(game.board());
GameState state = game.state();
```

`GameService.applyMove` loads a `Game`, reads its board and state to validate the move, then passes the same `Game` instance back into `GameStore.compareAndSave`, which uses `rawBoard()` as the CAS predicate and `entity().getId()` to target the row. A `false` return means another writer changed the board first; `applyMove` re-reads and re-validates rather than trusting a stale `Game`.
