# Game

A loaded game, opaque to callers outside the `repository` package. Wraps the JPA `GameEntity` so `GameStore.save` can reuse the exact row a prior `GameStore.load` already fetched instead of issuing a second `findById` query. This is the boundary type that lets `GameService` work with plain `List<String>` boards and the `GameState` enum without ever seeing `GameEntity`, `GameJpaRepository`, or `UUID`.

## Key Components

- `entity` - The wrapped `GameEntity`, package-private and immutable from outside `repository`.
- `Game(GameEntity entity)` - Package-private constructor; only `GameStore` can create instances.
- `board()` - Returns the board as `List<String>`, converted from the entity's 9-character string via `BoardUtils.convertToList`.
- `state()` - Returns the entity's `GameState`.
- `entity()` - Package-private accessor exposing the underlying `GameEntity` so `GameStore.save` can mutate and persist the same row without a redundant read.

## Usage Example

```java
Game game = gameStore.load(gameId);
List<String> board = new ArrayList<>(game.board());
GameState state = game.state();
```

`GameService.applyMove` loads a `Game`, reads its board and state to validate the move, then passes the same `Game` instance back into `GameStore.save`, which pulls out `entity()` to persist the updated board and state in one write.
