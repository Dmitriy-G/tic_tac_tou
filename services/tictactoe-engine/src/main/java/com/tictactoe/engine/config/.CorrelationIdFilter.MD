# CorrelationIdFilter

A servlet filter that makes every log line for a request greppable by a single correlation id. It reads the `X-Correlation-Id` header from the caller (or generates a UUID if absent), stores it in SLF4J's MDC under the `traceId` key for the duration of the request, and echoes it back on the response so the session service — and any other client — can tie its own logs to the engine's for the same operation.

## Key Components

- `@Component` - Registers the filter as a Spring bean so it is picked up automatically in the servlet filter chain.
- `HEADER` - The `X-Correlation-Id` HTTP header name used to read the incoming id and to echo it back on the response.
- `MDC_KEY` - The `traceId` key under which the correlation id is stored in SLF4J's MDC for structured logging.
- `doFilterInternal(...)` - Extends `OncePerRequestFilter`; resolves or generates the correlation id, puts it in MDC, sets it on the response header, delegates to the rest of the chain, and always clears MDC in a `finally` block to avoid leaking state across requests on a pooled thread.

## Usage Example

```
curl -X POST http://localhost:8081/games \
  -H "X-Correlation-Id: 3f2a1b4c-..." \
  -H "Content-Type: application/json" -d '{}'
```

If the header is supplied, every log line produced while handling this request carries `traceId=3f2a1b4c-...`, and the same value is returned in the response headers; if omitted, the filter generates one automatically.
