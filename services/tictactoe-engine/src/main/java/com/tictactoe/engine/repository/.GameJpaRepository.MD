# GameJpaRepository

Spring Data JPA repository for `GameEntity`, providing CRUD access to the `games` table in `engine_db`. Beyond the standard `JpaRepository` operations (`findById`, `save`, etc.), it adds one custom query, `compareAndSwapBoard`, the conditional `UPDATE` that makes concurrent moves safe without locking. This interface is private to the `repository` package; nothing outside it should depend on Spring Data directly.

## Key Components

- `@Repository` - Marks this as a Spring Data repository bean, enabling exception translation into Spring's `DataAccessException` hierarchy (handled by the inherited `handleDataAccess` in `BaseGlobalExceptionHandler`).
- `extends JpaRepository<GameEntity, UUID>` - Supplies standard CRUD and paging operations for `GameEntity`, keyed by its `UUID` id.
- `compareAndSwapBoard(UUID id, String expectedBoard, String newBoard, GameState state)` - `@Modifying` `UPDATE ... WHERE id = :id AND board = :expectedBoard`, so the write only lands if nobody else has changed the board since it was read. Returns the row count (`1` = won the race, `0` = lost it). `@Transactional` is present only because Spring Data requires it on `@Modifying` queries — the row lock lasts only for this single statement, not for the caller's load-validate-save cycle. `clearAutomatically = true` evicts the stale entity from the persistence context so a subsequent `load` in the same request sees the fresh board rather than a cached pre-update copy.

## Usage Example

```java
GameEntity entity = gameJpaRepository.findById(gameUuid)
        .orElseThrow(() -> new GameNotFoundException(gameId));
int updated = gameJpaRepository.compareAndSwapBoard(gameUuid, entity.getBoard(), newBoard, newState);
```

`GameStore` is the sole caller of this repository, keeping `GameEntity` and Spring Data types out of the rest of the engine service. See `docs/adr/0003-optimistic-concurrency-on-moves.md` for why this replaced a plain `save`.
