# GameController

REST controller exposing the engine's `/games` API. It holds no game-rule logic itself — it only validates input via `@Valid`, resolves a game id when the caller doesn't supply one, delegates to `GameService`, and returns the DTOs `GameService` produces. This is the sole HTTP entry point into the engine, the authority on board state, move validation, and outcome detection for the whole system.

## Key Components

- `@RestController` / `@RequestMapping("/games")` - Mounts all three endpoints under `/games`, matching the API contract exactly (no `/api/v1` prefix).
- `@Tag(name = "Games", ...)` - OpenAPI/Swagger grouping metadata for the generated docs.
- `GameController(GameService gameService)` - Constructor injection of the single collaborator; no field injection.
- `createGame(CreateGameRequest request)` - `POST /games` → `201`. Uses the caller-supplied `gameId` if present and non-blank, otherwise generates a new `UUID`, then delegates to `GameService.createGame`.
- `move(String gameId, MoveRequest move)` - `POST /games/{gameId}/move` → `200`. Validates the request body with `@Valid` and delegates to `GameService.applyMove`, which returns the authoritative board.
- `getGame(String gameId)` - `GET /games/{gameId}` → `200`. Delegates to `GameService.getGame` to fetch current board/status.

## Usage Example

```
POST /games
{"gameId": "3f2a1b4c-..."}   // optional body

POST /games/3f2a1b4c-.../move
{"symbol": "X", "position": 4}
```

The controller resolves the game id (generating one if omitted), then hands the request straight to `GameService`, which owns all rule enforcement and persistence.
