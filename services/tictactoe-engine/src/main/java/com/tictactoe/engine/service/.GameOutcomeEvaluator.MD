# GameOutcomeEvaluator

Resolves the outcome of a board immediately after a move has been applied to it — win, draw, or still in progress. This is where the "win-on-9th-cell beats draw" rule lives: win is always checked before fullness, so a winning move on the last empty cell is reported as a win, never a draw.

## Key Components

- `@Component` - Registers this as a Spring bean, injected into `GameService`.
- `GameOutcomeEvaluator(WinningLines winningLines)` - Constructor injection of the configured winning lines used for win detection.
- `resolve(List<String> board, Symbol symbol)` - Returns an `Outcome` for the board after `symbol`'s move: `X_WON`/`O_WON` if `symbol` completed a line, `DRAW` if the board is full with no winner, otherwise `IN_PROGRESS`.
- `isWin(List<String> board, Symbol symbol)` - Checks every configured winning line for three matching cells equal to `symbol`'s mark.
- `isFull(List<String> board)` - True when no cell equals `BoardUtils.EMPTY_CELL`.
- `Outcome(GameState state, Symbol winner)` - Nested record pairing the resulting `GameState` with the winning `Symbol` (`null` when there is no winner).

## Usage Example

```java
GameOutcomeEvaluator.Outcome outcome = outcomeEvaluator.resolve(board, move.symbol());
gameStore.compareAndSave(game, board, outcome.state());
return new MoveResponse(board, outcome.state(), StepStatus.CORRECT_STEP, outcome.winner());
```

`GameService.applyMove` calls `resolve` right after writing the new mark onto the board copy, then uses the returned `Outcome` to persist the game's new state (via the compare-and-swap `compareAndSave`) and build the move response.
