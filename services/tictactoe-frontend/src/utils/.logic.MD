# logic

Pure, UI-independent board helpers: constructing an empty board, converting the wire format to the in-memory one, deriving the winning line for the highlight, and diffing two boards to find which cell changed.

## Key Components

- `WINNING_LINES` - The 8 winning triples (3 rows, 3 columns, 2 diagonals), the same set the engine's `game.winning-lines` config encodes — duplicated here only because `calculateWinner` is a rendering aid, not a rules authority.
- `createEmptyBoard()` - Returns a fresh 9-cell array of `null`, used both for the reducer's initial state and on every `START` action.
- `normalizeBoard(board: string[])` - Converts the wire board (`'X'`/`'O'`/`'_'` strings) to `BoardState` (`Player | null`); any value other than `'X'`/`'O'` becomes `null`.
- `calculateWinner(squares)` - The UI's one remaining rule computation, kept only to derive the winning triple for `Board`'s highlight because the API doesn't return `winningLine` yet. The engine stays the sole authority on the actual outcome (`SessionResponse.status`/`winner`) — this is deletable the day the backend sends `winningLine` itself.
- `findChangedIndex(previous, next)` - Finds the first index where `next` has a non-null value that `previous` didn't, used by the reducer to recover which cell an SSE `MOVE` event changed (since `SessionEvent` carries a board snapshot but no `position`).

## Usage Example

```ts
const board = normalizeBoard(session.board)
const winningLine = calculateWinner(board)?.line ?? null
```

`App` uses `calculateWinner` for the highlight; `simulationReducer` uses `createEmptyBoard`, `normalizeBoard`, and `findChangedIndex` to build state from both SSE events and polled snapshots.
