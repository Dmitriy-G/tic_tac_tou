# MoveLog

Renders the move history as an ordered list, formatting each `MoveHistoryEntry` at render time via `formatMoveLogEntry` rather than storing pre-formatted strings — so a move replayed from a polled snapshot after a reconnect renders identically to one that arrived live over SSE.

## Key Components

- `interface MoveLogProps { entries: MoveHistoryEntry[] }` - The same shape `SessionResponse.moves` returns; `App` passes `state.moves` straight through.
- `aria-label="Move history"` on the `<aside>` - Names the region for assistive tech.
- `entries.length === 0` branch - Renders "No moves yet." before a simulation has produced any moves, so the board never starts with an ambiguous empty log.
- `key={entry.moveNumber}` - Stable key since move numbers are monotonically increasing and never reordered.

## Usage Example

```tsx
<MoveLog entries={state.moves} />
```

Because the reducer's `SNAPSHOT` action replaces `moves` wholesale from the polled session's own history, `MoveLog` survives a dropped-and-recovered SSE stream without losing entries.
