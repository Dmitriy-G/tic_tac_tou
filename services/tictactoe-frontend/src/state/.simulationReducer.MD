# simulationReducer

The state machine for one simulation run. `SimulationState` is a discriminated union on `phase`, with each variant carrying exactly the data valid for that phase — replacing what used to be four independently-settable flags (`status`, `isSimulating`, `isReconnecting`, `error`) plus a separately-tracked board ref that could disagree with what was on screen.

## Key Components

- `SimulationState` - Union of `idle | starting | running | reconnecting | finished | failed`; only `finished` carries `outcome` and only `failed` carries `message`, so the type itself makes `isSimulating === true` alongside a terminal status inexpressible.
- `SimulationAction` - `START | MOVE_APPLIED | STREAM_LOST | STREAM_RESTORED | SNAPSHOT | COMPLETED | FAILED`, one per event source (`useSimulation`'s SSE handlers, polling snapshots, and the `start()` call).
- `createInitialState()` - `{ phase: 'idle', board: createEmptyBoard(), moves: [] }`; passed to `useReducer` as the lazy initializer.
- `isTerminal(state)` / the guard at the top of `simulationReducer` - Terminal phases (`finished`/`failed`) are absorbing: every action except `START` is ignored once in one of them. This is what stops a late poll response — one already in flight when a `FAILED`/`COMPLETED` SSE event arrived — from reviving a session the UI already reported as done.
- `appendMove(moves, previousBoard, action)` - Derives the changed cell via `findChangedIndex` against the *previous reducer state's* board (not a separate ref), and appends a `MoveHistoryEntry`; a `null` `stepStatus` or no detected change is a no-op, not an error.
- `applySnapshot(state, session)` - Maps a polled `SessionResponse` onto a `SimulationState`: `CREATED`/`IN_PROGRESS` update board and moves in place, `FAILED` moves to the `failed` phase, anything else (`X_WON`/`O_WON`/`DRAW`) moves to `finished` with that status as `outcome`.

## Usage Example

```ts
const [state, dispatch] = useReducer(simulationReducer, undefined, createInitialState)
dispatch({ type: 'MOVE_APPLIED', board, stepStatus })
```

`useSimulation` is the sole owner of the reducer; every hook and component downstream (`App`, `StatusBanner`, `Board`, `MoveLog`) only ever reads the resulting `SimulationState`, never dispatches directly.
