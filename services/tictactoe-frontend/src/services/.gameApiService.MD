# gameApiService

All REST + SSE calls to `tictactoe-session`, made against the relative `/api` prefix — never a hardcoded host/port — so both `npm run dev` (via Vite's dev-server proxy) and the built container (via nginx) resolve it to the real service, per `docs/adr/0001-edge-routing-no-gateway.md`.

## Key Components

- `BASE_URL = '/api'` - The one place the prefix is defined; every exported function builds its URL from this.
- `class ApiError extends Error` - Carries `status`, `code`, and `traceId` from a failed response's body alongside the human-readable `message`, so callers (`useSimulation`) can distinguish "session creation failed" from "simulation failed" without re-parsing.
- `throwApiError(response)` - Defensive parsing: `response.json().catch(() => null)` so a non-JSON or empty error body still produces a usable `ApiError` instead of an unhandled rejection.
- `createSession()` - `POST /api/sessions` -> `SessionResponse`.
- `startSimulation(sessionId)` - `POST /api/sessions/{id}/simulate`; no return value, only throws on failure.
- `getSession(sessionId)` - `GET /api/sessions/{id}` -> `SessionResponse`. Rebuilds the full session view; used both to refresh while the SSE stream is down and to rehydrate the UI, since this endpoint is sufficient on its own.
- `subscribeToSession(sessionId, onEvent, onError, onOpen)` - Opens an `EventSource` on `GET /api/sessions/{id}/events`, listening for both the `update` and `failure` named SSE events and forwarding either to `onEvent`.

## Usage Example

```ts
const session = await createSession()
await startSimulation(session.sessionId)
const eventSource = subscribeToSession(session.sessionId, onEvent, onError, onOpen)
```

`useSimulation` calls `createSession`/`startSimulation` from `start()`, and `useSseSubscription` calls `subscribeToSession`; `getSession` is called from both `useSessionPolling` and, on failure paths, ad hoc rehydration.
