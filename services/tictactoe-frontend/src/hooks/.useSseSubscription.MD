# useSseSubscription

Owns the `EventSource` lifecycle only: opens on a session id, forwards parsed events to the given handlers, and closes on unmount or id change. Knows nothing about polling or simulation phases — that composition lives entirely in `useSimulation`.

## Key Components

- `interface SseHandlers { onEvent, onError, onOpen }` - The three callbacks `subscribeToSession` wires to `EventSource`'s `update`/`failure` listeners, `onerror`, and `onopen` respectively.
- `useSseSubscription(sessionId, handlers)` - No-ops when `sessionId` is `null` (before a session exists); otherwise opens a stream via `subscribeToSession` and returns `eventSource.close()` as the effect's cleanup.
- Effect dependency array (`[sessionId, onEvent, onError, onOpen]`) - Reopens the stream whenever the session id changes; `useSimulation` keeps the handler callbacks stable via `useCallback` so an unrelated re-render doesn't tear down and reopen the connection.

## Usage Example

```tsx
useSseSubscription(sessionId, { onEvent: handleEvent, onError: handleStreamError, onOpen: handleStreamOpen })
```

`useSimulation` is the sole caller; it supplies handlers that dispatch into `simulationReducer` and manage the reconnect timeout, but this hook itself has no reducer awareness.
