# useSimulation

Composes `useSseSubscription` and `useSessionPolling` around `simulationReducer` and exposes the one surface `App` needs: `{ state, isSimulating, start }`. This is the only hook `App` calls — everything else in `hooks/` is private to this composition.

## Key Components

- `RECONNECT_TIMEOUT_MS = 8000` - How long a dropped SSE stream is given to recover on its own (the browser's `EventSource` retries underneath this) before the UI gives up and marks the run failed.
- `handleEvent(event)` - Dispatches `MOVE_APPLIED` for every event with a board, plus `COMPLETED` or `FAILED` for terminal SSE events; normalizes the wire board via `normalizeBoard` first.
- `handleStreamError()` / `handleStreamOpen()` - On error, dispatches `STREAM_LOST` and arms a single reconnect timeout (guarded so a second error doesn't restart the clock); on reopen, clears the timeout and dispatches `STREAM_RESTORED`.
- `useSessionPolling(sessionId, state.phase === 'reconnecting', handleSnapshot)` - Polling is enabled for exactly the `reconnecting` phase, nothing else.
- `start()` - Always mints a **fresh** `sessionId` per run rather than reusing a previous one: a session is single-use, and the backend now rejects re-simulating a completed one (`409 SESSION_ALREADY_COMPLETED`). Creates the session, then starts the simulation; any failure (network, `ApiError`, or otherwise) dispatches `FAILED` with a message.
- `isSimulating` - Derived from `state.phase` (`starting | running | reconnecting`), never stored separately, so it can never disagree with the phase.

## Usage Example

```tsx
const { state, isSimulating, start } = useSimulation()
```

`App` calls this once; the returned `state` drives `StatusBanner`, `Board`, and `MoveLog`, `isSimulating` disables the start button while a run is in flight, and `start` is the button's `onClick`.
