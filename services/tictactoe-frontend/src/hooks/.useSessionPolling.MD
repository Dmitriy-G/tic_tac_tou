# useSessionPolling

`setInterval` over `GET /sessions/{id}`, active only while `enabled`. Knows nothing about SSE — the caller (`useSimulation`) decides when polling should run, which today is only while `phase === 'reconnecting'`. This is the SSE-fallback half of the CLAUDE.md requirement: "if the stream errors, fall back to polling."

## Key Components

- `POLL_INTERVAL_MS = 1000` - Fallback cadence while the stream is down.
- `useSessionPolling(sessionId, enabled, onSnapshot)` - No-ops (clears any interval and returns) whenever `!enabled || !sessionId`, so the interval only exists during an active reconnect window.
- `getSession(sessionId).then(onSnapshot).catch(() => {})` - A failed poll is swallowed rather than surfaced — it's transient, and `useSimulation`'s own reconnect timeout is what eventually gives up and marks the run failed.
- Cleanup function (`window.clearInterval`) - Returned from the effect so a poll interval never survives past `sessionId`/`enabled` changing or the component unmounting.

## Usage Example

```tsx
useSessionPolling(sessionId, state.phase === 'reconnecting', handleSnapshot)
```

`useSimulation` enables this hook exactly while the SSE subscription reports the stream lost, and disables it again once the stream reopens or the run reaches a terminal state.
