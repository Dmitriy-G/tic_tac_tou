# BaseGlobalExceptionHandler

Shared `@RestControllerAdvice` base extended by both services' concrete exception handlers. Only faults land here — rule outcomes like `StepStatus` stay on their HTTP-200 channel and never reach this class. Centralizes the mapping from every exception type either service can throw to the single `ErrorResponse` body shape.

## Key Components

- `log` - `private static final Logger`; used for warn-level logging on client errors and error-level logging (with stack trace) on 5xx faults.
- `handleBaseException(BaseException, HttpServletRequest)` - Handles all app-specific faults; logs at `error` or `warn` depending on whether the mapped HTTP status is >= 500, then delegates to `respond`.
- `handleHandlerMethodValidation(HandlerMethodValidationException, HttpServletRequest)` - Handles Spring 6.1+ validation failures on `@PathVariable`/`@RequestParam`; without this handler these fall through to the catch-all and get mislabelled `INTERNAL_ERROR` instead of `VALIDATION_ERROR`.
- `handleMethodArgumentNotValid(MethodArgumentNotValidException, HttpServletRequest)` - Handles `@Valid` request-body failures, collecting field errors into the `ErrorResponse`.
- `handleConstraintViolation(ConstraintViolationException, HttpServletRequest)` - Handles bean-validation constraint violations outside the standard MVC binding path.
- `handleMalformedBody(HttpServletRequest)` - Handles unparsable JSON bodies as 400 `MALFORMED_REQUEST`.
- `handleMissingParameter(MissingServletRequestParameterException, HttpServletRequest)` - Handles missing required request parameters as 400 `VALIDATION_ERROR`.
- `handleTypeMismatch(MethodArgumentTypeMismatchException, HttpServletRequest)` - Handles request parameters that fail to convert to their declared type.
- `handleIllegalArgument(IllegalArgumentException, HttpServletRequest)` - Handles stray `IllegalArgumentException`s as 400 `MALFORMED_REQUEST`.
- `handleMethodNotSupported(HttpRequestMethodNotSupportedException, HttpServletRequest)` - Handles wrong HTTP verb on a known path as 405.
- `handleMediaTypeNotSupported(HttpMediaTypeNotSupportedException, HttpServletRequest)` - Handles unsupported `Content-Type` as 415.
- `handleDataAccess(DataAccessException, HttpServletRequest)` - Handles Spring Data/JDBC failures as 503 `DATABASE_ERROR`, never leaking the underlying exception message.
- `handleUnexpected(Exception, HttpServletRequest)` - Catch-all; logs the full stack trace but returns a fixed message (never `ex.getMessage()`, which could leak internals) as 500 `INTERNAL_ERROR`.
- `toFieldError(ConstraintViolation<?>)` - Private helper mapping a `ConstraintViolation` to an `ErrorResponse.FieldError`.
- `respond(ErrorCode, String, HttpServletRequest, List<ErrorResponse.FieldError>)` - Private helper that builds the `ErrorResponse` body (stamping the correlation id from MDC) and wraps it in a `ResponseEntity` with the code's HTTP status.

## Usage Example

```java
@RestControllerAdvice
public class EngineExceptionHandler extends BaseGlobalExceptionHandler {
}
```

Each service declares a thin, concrete `@RestControllerAdvice` subclass with no additional logic; all exception-to-response mapping is inherited from this shared base, guaranteeing an identical error shape from both services.
