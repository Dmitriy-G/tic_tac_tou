# ErrorResponse

The single error body shape returned by both services on any fault, matching the API contract's error response format exactly. `traceId` carries the correlation id (the `sessionId`, put in MDC) and `fieldErrors` is populated only for validation failures.

## Key Components

- `@JsonInclude(JsonInclude.Include.NON_NULL)` - Omits null fields (e.g. `fieldErrors` on non-validation errors, `traceId` when absent) from the serialized JSON instead of emitting `null`.
- `timestamp` - `Instant` record component; when the error occurred.
- `status` - `int` record component; the numeric HTTP status, mirrored from `ErrorCode`.
- `code` - `String` record component; the stable wire error code, e.g. `"CELL_OCCUPIED"`.
- `message` - `String` record component; a human-readable description of the fault.
- `path` - `String` record component; the request URI that triggered the fault.
- `traceId` - `String` record component; the correlation id for cross-service log grepping.
- `fieldErrors` - `List<FieldError>` record component; per-field validation messages, or `null` when not applicable.
- `FieldError` - Nested record `(String field, String message)`; one bean-validation failure.
- `of(ErrorCode, String, String, String)` - Static factory building an `ErrorResponse` with no field errors.
- `of(ErrorCode, String, String, String, List<FieldError>)` - Static factory building an `ErrorResponse` with field errors attached.

## Usage Example

```java
ErrorResponse body = ErrorResponse.of(ErrorCode.CONFLICT, "Cell 4 is already occupied", "/games/3f2a.../move", traceId);
return ResponseEntity.status(409).body(body);
```

`BaseGlobalExceptionHandler.respond` uses these factories to build the exact error shape documented in the API contract for every fault raised by either service.
