# RuleBasedMoveStrategy

The `ADVANCED` `MoveStrategy` implementation: a deterministic, non-random player following the win > block > center > corner > side priority order described in the root CLAUDE.md, for a smarter automated player than `RandomMoveStrategy`'s uniform pick.

## Key Components

- `WINNING_LINES` - The 8 winning triples (3 rows, 3 columns, 2 diagonals), a local copy for this heuristic only — the engine remains the sole authority on actual outcome detection; this never influences the real game result, only which cell this strategy proposes next.
- `selectMove(List<String> board, String symbol)` - Tries, in order: a move that completes a line for `symbol` (`findWinningMove(board, symbol)`); a move that blocks the opponent's winning line (`findWinningMove(board, opponentOf(symbol))`); the center (index 4); the first empty corner (`0, 2, 6, 8`); the first empty side (`1, 3, 5, 7`). Throws `IllegalStateException` if none of those apply, i.e. the board is full — the same "caller error, fail loudly" contract as `RandomMoveStrategy`.
- `findWinningMove(String board, symbol)` - Scans `WINNING_LINES` for a line with exactly two cells matching `symbol` and one empty cell, returning that empty cell's index, or `null` if no such line exists. Used both for the win check (with `symbol`) and the block check (with the opponent's symbol).
- No injected `Random` - Unlike `RandomMoveStrategy`, this strategy is fully deterministic given the board and symbol, so it needs no random source at all.

## Usage Example

```java
case "ADVANCED" -> new RuleBasedMoveStrategy();
```

`MoveStrategyResolver.createStrategy` wires this in for symbols configured with the `ADVANCED` strategy type; `RuleBasedMoveStrategyTest` covers win, block, center, corner, side, and the full-board exception case directly.
