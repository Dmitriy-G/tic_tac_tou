# MoveStrategyResolver

Resolves the `MoveStrategy` to use for a given symbol (`X` or `O`) at startup, based on configuration. Lets X and O play with different simulation strategies (SIMPLE &rarr; `RandomMoveStrategy`, ADVANCED &rarr; `RuleBasedMoveStrategy`); only SIMPLE is wired to real behavior differences today since `RandomMoveStrategy` is the currently exercised path, but both strategy types are constructible. Builds its per-symbol map once in the constructor rather than re-resolving on every move.

## Key Components

- `@Component` - Registers this as a Spring-managed bean, injected wherever a symbol's move strategy is needed.
- `strategiesBySymbol` - Immutable `Map<String, MoveStrategy>` with exactly the `"X"` and `"O"` entries, built once at construction time.
- `MoveStrategyResolver(Random, String, String)` - Constructor; takes the shared, injected `Random` (never `new Random()` inline, per project convention) plus the `simulation.strategy.x`/`simulation.strategy.o` config values (default `SIMPLE` for both) and builds a strategy for each symbol.
- `resolve(String symbol)` - Looks up the strategy for a symbol; throws `IllegalArgumentException` for anything other than `"X"`/`"O"`.
- `createStrategy(String type, Random random)` - Static factory mapping the config string (case-insensitively) to a strategy instance: `SIMPLE` &rarr; `new RandomMoveStrategy(random)`, `ADVANCED` &rarr; `new RuleBasedMoveStrategy()`, anything else &rarr; `IllegalArgumentException`.

## Usage Example

```yaml
simulation:
  strategy:
    x: SIMPLE
    o: ADVANCED
```

```java
MoveStrategy xStrategy = moveStrategyResolver.resolve("X");
int position = xStrategy.selectMove(board, Symbol.X);
```

With this config, X plays randomly while O plays the win-block-center-corner-side rule-based strategy; the simulation loop asks the resolver for the correct strategy on every move rather than hardcoding one.
