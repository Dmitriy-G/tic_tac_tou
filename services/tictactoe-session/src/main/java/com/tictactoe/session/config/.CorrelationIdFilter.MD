# CorrelationIdFilter

Servlet filter that establishes the correlation id used to grep every log line for a given request or simulation. Reads `X-Correlation-Id` from the incoming request, generates a random UUID if the header is absent or blank, stores it in SLF4J's MDC under the key `traceId`, echoes it back on the response, and clears MDC once the request completes. `GameEngineClientImpl` forwards the same value to the engine on every outbound call, and the simulation-starting service captures it for the background simulation thread, since MDC does not propagate to new threads on its own.

## Key Components

- `@Component` - Registers this filter as a Spring bean so it is picked up by the servlet filter chain.
- `HEADER` - Public constant `"X-Correlation-Id"`, the HTTP header name read from the request and written to the response.
- `MDC_KEY` - Public constant `"traceId"`, the MDC key under which the correlation id is stored for structured logging.
- `doFilterInternal(HttpServletRequest, HttpServletResponse, FilterChain)` - Extracts or generates the correlation id, puts it in MDC, sets it on the response, delegates to the rest of the filter chain, and clears MDC in a `finally` block so it never leaks into the next request handled by the same thread.

## Usage Example

```java
String traceId = MDC.get(CorrelationIdFilter.MDC_KEY);
restClient.post().header(CorrelationIdFilter.HEADER, traceId);
```

Shows how downstream code (here, `GameEngineClientImpl`) reads the correlation id this filter placed in MDC and forwards it as a header on the outbound call to the engine, keeping the same id traceable across both services' logs.
