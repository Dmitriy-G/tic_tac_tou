# SseEmitterRegistry

Manages the SSE (`text/event-stream`) subscribers for every session, publishes events to them, and replays a per-session backlog so late subscribers (and reconnecting ones) never miss moves. Backs `GET /sessions/{id}/events` and is the mechanism behind the "late subscriber gets the backlog then live events" requirement in the root CLAUDE.md.

## Key Components

- `@Component` - Registers the class as a Spring bean.
- `MAX_BACKLOG_PER_SESSION` - Caps the retained backlog at 32 events per session, evicting the oldest once exceeded.
- `emitters` - `ConcurrentHashMap<String, List<SseEmitter>>`; a session can have multiple emitters since multiple browser tabs can watch the same session — a second `register` must not evict the first.
- `backlogs` - `ConcurrentHashMap<String, List<BacklogEntry>>` of published events per session, each tagged with a strictly increasing id.
- `sequences` - `ConcurrentHashMap<String, AtomicLong>` generating that increasing id per session; deliberately not `progress.moveNumber()` because that number doesn't advance on a rejected move, which would collide two different events on the same id.
- `SseEmitterRegistry()` / `SseEmitterRegistry(Supplier<SseEmitter> emitterFactory)` - Public no-arg constructor used by Spring; package-private factory-injecting constructor used by tests to substitute a recording emitter.
- `register(String sessionId, String lastEventId)` - Creates and tracks a new emitter for the session, wires completion/timeout/error cleanup, and replays backlog entries after `lastEventId` (or the entire backlog for a brand-new subscriber, passing `null`).
- `publish(String sessionId, SessionEvent event)` - Assigns the next sequence id, appends to the backlog, and sends the event to every current emitter for the session; an `IOException` from one dead emitter (a closed browser tab) is isolated to that emitter and doesn't stop delivery to the rest.
- `complete(String sessionId)` - Clears the backlog/sequence/emitters for a session and completes every emitter, called once a simulation finishes.
- `heartbeat()` - `@Scheduled` method sending an SSE comment frame to every open emitter on a configurable interval, resetting idle timers along the whole chain (proxy, load balancer, browser) even though `EventSource` ignores comment frames.
- `replayBacklog`, `parseLastEventId`, `addToBacklog`, `sendQuietly`, `eventNameFor`, `removeEmitter` - Private helpers for backlog replay, defensive `Last-Event-ID` parsing, backlog trimming, best-effort sending, event naming (`failure` vs `update`), and emitter cleanup.
- `BacklogEntry` - Private record pairing a sequence id, event name, and `SessionEvent` for replay.

## Usage Example

```java
SseEmitter emitter = emitterRegistry.register(sessionId, lastEventId);
emitterRegistry.publish(sessionId, new SessionEvent(...));
```

`SessionService.subscribe` registers a new client's emitter (replaying backlog if reconnecting), and `SimulationEventPublisher` publishes each move/failure event as the simulation progresses.
