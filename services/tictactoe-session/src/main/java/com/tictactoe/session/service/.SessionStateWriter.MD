# SessionStateWriter

Persists a simulation's progress and terminal outcomes to `session_db.sessions` and
`session_db.session_moves`. Replaces the deleted `SessionStateStore` (in-memory `LiveState`) and
`SimulationStateWriter` (the old `simulations` table) now that one session is one game and the
session row is the single durable source of truth — see `docs/adr/0004-session-is-the-game.md`.

## Key Components

- `@Component` - Registers the class as a Spring bean.
- `SessionStateWriter(SessionJpaRepository, SessionMoveJpaRepository)` - Constructor injection of both repositories.
- `recordMove(String sessionId, SimulationProgress progress, MoveRecord move)` - Inserts a `SessionMoveEntity` row only when `move.stepStatus()` is `CORRECT_STEP` (a rejected attempt never advances `moveNumber`, so persisting it would collide with the composite primary key), then always updates the `SessionEntity` row's board/status/winner/errorsCount from `progress`, setting `finishedAt` only once the state is no longer `IN_PROGRESS`. One `INSERT` plus one `UPDATE` per accepted move — durable, and the known scaling ceiling for mass simulation (see the ADR).
- `persistTerminal(String sessionId, SimulationProgress progress)` - Closes the loop-exit hole: if `SimulationRunner`'s loop stopped because it exhausted its move budget without the engine ever returning a terminal state, this forces a `FAILED` row via `fail`. A no-op when `progress` is already terminal, the normal case since the last `recordMove` call already wrote it.
- `fail(String sessionId, ErrorCode errorCode, String message)` - Persists a terminal `FAILED` outcome with the given error code/message. Swallows its own `RuntimeException` (logs and returns) so a failure to record a failure can never mask the original exception `SimulationRunner` is already handling.
- `findOrThrow(String sessionId)` - Private lookup that throws `InternalException` if the session row has vanished mid-run — a defensive guard against an impossible-but-not-quite-impossible state.
- `winnerOf(GameState state)` - Private helper deriving the winning `Symbol` (`X`/`O`, or `null`) from the terminal `GameState`, without needing `SimulationProgress` itself to track a winner field.

## Usage Example

```java
MoveRecord move = step.execute(sessionId, progress);
stateWriter.recordMove(sessionId, progress, move);
...
stateWriter.persistTerminal(sessionId, progress);
```

Called once per loop iteration and once after the loop exits in `SimulationRunner.run`, ensuring
`sessions` always ends with a terminal row regardless of how the loop finished, and that
`session_moves` holds the full, durable, replayable move history — readable by `GET
/sessions/{id}` even after a process restart.
