# SessionResponse

The JSON body returned by `POST /sessions`, `GET /sessions/{sessionId}` and used as the basis for `SessionEvent` payloads — the outward-facing view of a session's full state, matching the API contract's `{sessionId, status, board, moves[], winner, error}` shape (with the error split into `errorCode`/`errorMessage`).

## Key Components

- `sessionId` - The session identifier, which is also the engine's `gameId`.
- `status` - The shared `GameState` enum: `CREATED`/`IN_PROGRESS`/`X_WON`/`O_WON`/`DRAW`/`FAILED`/`CANCELLED` per the session state machine.
- `board` - The current 9-cell board snapshot, sourced from the engine's authoritative response — the session never maintains its own copy.
- `moves` - The full ordered move history as a `List<MoveRecord>`, letting the frontend render a numbered move log and replay the game.
- `winner` - The shared `Symbol` enum value of the winning player, or null if not won.
- `errorCode` / `errorMessage` - Populated when `status` is `FAILED`, giving the frontend enough detail to show the error banner.

## Usage Example

```java
return new SessionResponse(sessionId, GameState.IN_PROGRESS, board, moves, null, null, null);
```

Returned from `SessionController.getSession`, this is what a page-refresh mid-simulation uses to rehydrate the board and move log instead of showing an empty board for a running game.
