# SimulationProgress

Mutable, package-private accumulator for a single simulation run: the current board, `GameState`, whose turn's move number it is, and how many rejected/errored steps have occurred. Owns the loop-termination guarantee that keeps `SimulationRunner`'s `while` loop bounded: every `recordStep` call advances exactly one of `moveNumber` or `errorsCount`, `moveNumber` is capped at `MAX_MOVES` (9), and `errorsCount` forces a terminal `FAILED` state once it exceeds `MAX_ERRORS` (10) — so `hasNextIteration()` can run at most `MAX_MOVES + MAX_ERRORS + 1` = 20 times.

## Key Components

- `MAX_MOVES` - Cap of 9 on successful moves, matching the 9-cell board and the "hard cap of 9 iterations" safety net from the root CLAUDE.md.
- `MAX_ERRORS` - Cap of 10 on rejected/errored steps before the run is forced to `FAILED`, independent of the move cap.
- `board`, `gameState`, `moveNumber`, `errorsCount` - The mutable run state; `gameState` starts `IN_PROGRESS`, `moveNumber` starts at 1 (X moves first).
- `start(List<String> board)` - Static factory creating a fresh `SimulationProgress` from the engine's initial board.
- `hasNextIteration()` - True while the run isn't finished and `moveNumber` hasn't exceeded `MAX_MOVES`; drives the `SimulationRunner` loop condition.
- `currentSymbol()` - Derives whose turn it is (`X` on odd `moveNumber`, `O` on even) without a separate stored field.
- `board()`, `moveNumber()`, `errorsCount()`, `gameState()` - Read accessors used by `SimulationStep` and `SessionStateWriter`.
- `isFinished()` - True once `gameState` is anything other than `IN_PROGRESS`.
- `recordStep(MoveResponse response)` - Updates `board`/`gameState` from the engine's response; on a non-`CORRECT_STEP` result increments `errorsCount` (and forces `FAILED` past `MAX_ERRORS`), otherwise advances `moveNumber`.

## Usage Example

```java
SimulationProgress progress = SimulationProgress.start(initialBoard);
while (progress.hasNextIteration()) {
    MoveRecord move = step.execute(sessionId, progress);
    stateWriter.recordMove(sessionId, progress, move);
}
```

The core loop in `SimulationRunner.run`: each iteration lets `SimulationStep` attempt a move and calls `progress.recordStep` internally, and the loop exits once the game reaches a terminal state or the move/error budget is exhausted. Kept unchanged by the session-is-the-game refactor — it is the loop's state machine and doesn't care where its state ends up persisted.
