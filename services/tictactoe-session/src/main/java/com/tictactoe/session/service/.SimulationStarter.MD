# SimulationStarter

Validates and kicks off a simulation run for `POST /sessions/{sessionId}/simulate`, handling the 409 conflict cases (unknown session, already-running simulation, and the concurrent-double-click race) before handing execution off to `SimulationRunner` on a virtual thread.

## Key Components

- `@Component` - Registers the class as a Spring bean.
- `SimulationStarter(SessionJpaRepository, SimulationJpaRepository, SimulationRunner, SessionStateStore)` - Constructor injection of all four collaborators.
- `start(String sessionId)` - Validates the session exists (`SessionNotFoundException` otherwise), rejects if a simulation is already `IN_PROGRESS` for it (`SimulationAlreadyRunningException`), builds and saves a new `SimulationEntity` row, marks the live state running via `SessionStateStore.markRunning`, and spawns `runner.run` on a fresh virtual thread. Catches `DataIntegrityViolationException` from the save as the race-losing signal — two concurrent requests both passed the existence check, and the database's unique partial index on `(session_id) WHERE status = 'IN_PROGRESS'` rejected the second insert — turning it into the same `SimulationAlreadyRunningException` as the pre-check.
- Trace id capture - Reads the correlation id from MDC before spawning the thread (MDC doesn't propagate across `Thread.ofVirtual().start()`), falling back to the `sessionId` itself when nothing is in MDC scope (e.g. a test calling `start()` directly, outside a request).

## Usage Example

```java
void simulate(String sessionId) {
    simulationStarter.start(sessionId);
}
```

`SessionService.simulate` is a thin delegate to this class, which does all the validation and orchestration work behind the `/simulate` endpoint.
