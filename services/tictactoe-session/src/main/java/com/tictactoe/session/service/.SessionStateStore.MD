# SessionStateStore

Holds each session's board and move history in memory for the life of the process. Deliberately not persisted to `session_db` — persisting it would duplicate the engine's authoritative board, an anti-pattern the root CLAUDE.md calls out explicitly. All mutation goes through `Map.compute` (never a plain get-then-put) so a concurrent GET and a concurrent move-landing never tear each other's view. Both `GET /sessions/{id}` and the SSE stream are populated from this store, which is what makes the stream an optimisation layered on top rather than the sole source of truth.

## Key Components

- `@Component` - Registers the class as a Spring bean, shared as a singleton across requests and the virtual threads running simulations.
- `state` - `ConcurrentHashMap<String, LiveState>` keyed by `sessionId`, the actual live storage.
- `initialize(String sessionId)` - Seeds a fresh `LiveState.initial()` entry when a session is created.
- `markRunning(String sessionId)` - Resets to an initial state tagged `IN_PROGRESS` when a simulation starts.
- `recordMove(String sessionId, int moveNumber, Symbol symbol, int position, MoveResponse response)` - Appends a `MoveRecord` to the move history and replaces the board/status with the engine's authoritative response, via `compute` for atomicity.
- `recordFailure(String sessionId, ErrorCode errorCode, String errorMessage)` - Transitions the live state to `FAILED`, preserving the board and moves accumulated so far while attaching the error code/message.
- `get(String sessionId)` - Returns the current `LiveState`, or a fresh initial one if the session isn't tracked (defensive default rather than `null`).
- `LiveState` record - Immutable snapshot of `status`, `board`, `moves`, `winner`, `errorCode`, `errorMessage`; `initial()` builds the `CREATED` state with an all-empty board; `withStatus` returns a copy with a different status.

## Usage Example

```java
stateStore.initialize(sessionId);
stateStore.markRunning(sessionId);
stateStore.recordMove(sessionId, 1, Symbol.X, 4, moveResponse);
SessionStateStore.LiveState liveState = stateStore.get(sessionId);
```

Shows the lifecycle a session's live state passes through: seeded at creation, flipped to running when `/simulate` starts, then updated after every move the simulation loop records.
