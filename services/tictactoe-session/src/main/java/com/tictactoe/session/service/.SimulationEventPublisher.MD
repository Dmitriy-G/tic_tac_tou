# SimulationEventPublisher

Bridges a simulation step's outcome to the live SSE stream (`SseEmitterRegistry`) only — durable
persistence is `SessionStateWriter`'s job, not this class's. Kept separate from persistence so a
slow or failing subscriber can never block a move from being saved.

## Key Components

- `@Component` - Registers the class as a Spring bean.
- `SimulationEventPublisher(SseEmitterRegistry emitterRegistry)` - Constructor injection of its one collaborator; no store dependency.
- `publishMove(String sessionId, MoveResponse response)` - Publishes a `SessionEvent` (type `MOVE` or `COMPLETED` depending on whether `gameState` is terminal) built entirely from `response`, carrying the updated board and step status, tagged with the current trace id from MDC.
- `publishFailure(String sessionId, ErrorCode errorCode, String message)` - Publishes a `FAILED` `SessionEvent` — the only way a client that already received the 202 from `/simulate` learns the run died, since there's no HTTP response left to fail into.
- `complete(String sessionId)` - Delegates to `SseEmitterRegistry.complete` to close out all emitters for the session once the run is fully done.

## Usage Example

```java
eventPublisher.publishMove(sessionId, response);
```

Called once per move attempt inside `SimulationStep.execute`, keeping subscribers in sync with the
engine's authoritative response; `SimulationRunner` separately calls `SessionStateWriter.recordMove`
for the durable side of the same event.
