# SimulationEventPublisher

Bridges a simulation step's outcome to both the durable live state (`SessionStateStore`) and the live SSE stream (`SseEmitterRegistry`), so every move or failure is recorded and broadcast in one call from `SimulationStep`/`SimulationRunner`.

## Key Components

- `@Component` - Registers the class as a Spring bean.
- `SimulationEventPublisher(SseEmitterRegistry emitterRegistry, SessionStateStore stateStore)` - Constructor injection of its two collaborators.
- `publishMove(String sessionId, int moveNumber, String symbol, int position, MoveResponse response)` - Records the move in `SessionStateStore`, then publishes a `SessionEvent` (type `MOVE` or `COMPLETED` depending on whether `gameState` is terminal) carrying the updated board and step status, tagged with the current trace id from MDC.
- `publishFailure(String sessionId, ErrorCode errorCode, String message)` - Records the failure in `SessionStateStore` and publishes a `FAILED` `SessionEvent` — the only way a client that already received the 202 from `/simulate` learns the run died, since there's no HTTP response left to fail into.
- `complete(String sessionId)` - Delegates to `SseEmitterRegistry.complete` to close out all emitters for the session once the run is fully done.

## Usage Example

```java
eventPublisher.publishMove(sessionId, progress.moveNumber(), symbol, position, response);
```

Called once per accepted move inside `SimulationStep.execute`, keeping the session's persisted live view and its subscribers in sync with the engine's authoritative response.
