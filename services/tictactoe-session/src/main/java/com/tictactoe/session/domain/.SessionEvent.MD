# SessionEvent

The payload published on a session's SSE stream. `type` discriminates what the client should do with the event: `MOVE` is an in-progress board update, `COMPLETED` is a terminal engine outcome (win/draw), and `FAILED` is a simulation fault after which no further board updates will arrive. A closed SSE stream alone is indistinguishable from a transient network blip, so the simulation code must always emit an explicit `FAILED` event before completing the stream on any fault path.

## Key Components

- `sessionId` - The session (= game) this event belongs to.
- `type` - The `EventType` discriminator: `MOVE`, `COMPLETED`, or `FAILED`.
- `board` - The current 9-cell board snapshot at the time of the event.
- `stepStatus` - The shared `StepStatus` enum value describing this step's outcome.
- `winner` - The winning symbol, if the event represents a completed win; null otherwise.
- `errorCode` / `errorMessage` - Populated only on `FAILED` events, mirroring the service's standard error shape.
- `traceId` - The correlation id (from `CorrelationIdFilter`/MDC) for the simulation run that produced this event, so a client-visible event can be tied back to server logs.
- `EventType` - Nested enum with constants `MOVE`, `COMPLETED`, `FAILED`.

## Usage Example

```java
emitter.send(new SessionEvent(sessionId, SessionEvent.EventType.MOVE, board,
        StepStatus.IN_PROGRESS, null, null, null, traceId));
```

Emitted after each simulated move; the frontend's `EventSource` listener switches on `type` to update the board, show the winning line, or display the error banner described in the project's frontend requirements.
