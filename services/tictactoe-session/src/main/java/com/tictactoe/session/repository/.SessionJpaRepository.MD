# SessionJpaRepository

Spring Data JPA repository for `SessionEntity`, now the single source of truth for
`session_db.sessions` — status, board, winner, error info and timing, not just an identity row.

## Key Components

- `@Repository` - Marks the interface as a Spring Data repository bean, eligible for exception translation into Spring's `DataAccessException` hierarchy.
- `JpaRepository<SessionEntity, UUID>` - Supplies `save`, `existsById`, `findById`, etc. for standard reads/writes.
- `claimForSimulation(UUID id, Instant startedAt)` - `@Modifying` conditional `UPDATE ... SET status = IN_PROGRESS, started_at = :startedAt WHERE id = :id AND status = CREATED`. Returns the row count: `1` means this call claimed the session, `0` means it was no longer `CREATED`. This single statement is the entire double-simulate guard — no separate existence/status pre-check query and no unique index, since the `UPDATE`'s `WHERE` clause is the check.

## Usage Example

```java
if (sessionRepository.claimForSimulation(id, Instant.now()) == 0) {
    // someone else claimed it, or it was never CREATED
}
```

Used by `SimulationStarter` as the compare-and-swap guard against concurrent `/simulate` calls, and by `SessionService`/`SessionStateWriter` for the plain reads and writes of a session's full state.
