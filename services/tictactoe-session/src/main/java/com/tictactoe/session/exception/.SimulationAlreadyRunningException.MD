# SimulationAlreadyRunningException

Thrown when `POST /sessions/{sessionId}/simulate` is called for a session whose status is
`IN_PROGRESS` — the "UI double-click" case called out in the root CLAUDE.md. Extends the shared
`ConflictException`, so the controller advice turns it into HTTP 409 with
`code=SIMULATION_ALREADY_RUNNING`.

## Key Components

- `SimulationAlreadyRunningException(String sessionId)` - Builds the exception with `ErrorCode.SIMULATION_ALREADY_RUNNING` and a message naming the session.

## Usage Example

```java
if (sessionRepository.claimForSimulation(id, Instant.now()) == 0) {
    throw session.getStatus() == GameState.IN_PROGRESS
            ? new SimulationAlreadyRunningException(sessionId)
            : new SessionAlreadyCompletedException(sessionId);
}
```

Thrown by `SimulationStarter.start` when the compare-and-swap in
`SessionJpaRepository.claimForSimulation` loses because another call already claimed the session —
covers both the sequential double-click and the true concurrent race in one code path, since the
CAS is the only guard.
