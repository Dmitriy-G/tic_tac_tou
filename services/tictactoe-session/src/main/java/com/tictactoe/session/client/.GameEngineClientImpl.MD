# GameEngineClientImpl

`RestClient`-based implementation of `GameEngineClient`, the session service's sole HTTP entry point to the Game Engine Service. Configures explicit connect and read timeouts (the most commonly missed requirement in this kind of service, per the project's anti-patterns list), wraps every call in a Resilience4j `Retry` with exponential backoff, forwards the request's correlation id to the engine, and classifies every non-2xx response or transport failure into one of the typed `client` exceptions before it ever reaches a caller — no raw Spring Web exception leaks out of this class.

## Key Components

- `@Component` - Registers this as the Spring-managed `GameEngineClient` bean.
- `restClient` - The configured `RestClient` used for all engine calls; built once with explicit timeouts and the engine's base URL.
- `errorHandler` - A `DefaultResponseErrorHandler` used inside `.onStatus(...)` to turn any error status into a `HttpStatusCodeException` that `classify` can then categorize.
- `retry` - The Resilience4j `Retry` instance, configured to retry only `EngineUnavailableException` with exponential random backoff.
- `GameEngineClientImpl(RestClient.Builder, String, long, long, int, long)` - `@Autowired` constructor; reads `game-engine.base-url` and the connect/read timeout and retry properties from config, and builds the underlying `RestClient` via `buildRestClient`.
- `GameEngineClientImpl(RestClient, int, long)` - Package-private test seam: accepts an already-built `RestClient` (e.g. one bound to `MockRestServiceServer`) so a test's own request factory isn't overwritten by the primary constructor's `.requestFactory(...)` call.
- `buildRestClient(...)` - Static helper that applies `ClientHttpRequestFactorySettings` (connect/read timeouts) and the base URL to the given `RestClient.Builder`.
- `createGame(String gameId)` - Public API: creates a game on the engine, retried via `withRetry`.
- `move(String gameId, String player, int position)` - Public API: submits a move to the engine, retried via `withRetry`.
- `doCreateGame(String gameId)` - Performs the `POST /games` call; throws `EngineBadResponseException` if the response or its board is null, otherwise delegates unexpected failures to `classify`.
- `doMove(String gameId, String player, int position)` - Performs the `POST /games/{gameId}/move` call; delegates any failure to `classify`.
- `withRetry(Supplier<T> call)` - Wraps a call with the configured `Retry` via `Retry.decorateSupplier`.
- `correlationId()` - Reads the current correlation id from MDC (set by `CorrelationIdFilter`), defaulting to an empty string if absent.
- `classify(Exception e, String gameId)` - Maps a caught exception to the appropriate typed exception: `ResourceAccessException`/`HttpServerErrorException` &rarr; `EngineUnavailableException`, 404 &rarr; `EngineStateLostException`, other 4xx &rarr; `EngineContractViolationException`, anything else &rarr; `EngineBadResponseException`. Never passes the engine's downstream HTTP status straight through, since the session and engine have distinct failure semantics for the same status code.

## Usage Example

```java
GameEngineClient client = new GameEngineClientImpl(
        RestClient.builder(), "http://localhost:8081", 2000, 3000, 3, 200);
CreateGameResponse game = client.createGame(sessionId);
MoveResponse afterMove = client.move(sessionId, "X", 4);
```

Constructs the client against a running engine instance and drives one full move; in production, Spring wires the `@Autowired` constructor from `application.yml`'s `game-engine.*` properties instead.
