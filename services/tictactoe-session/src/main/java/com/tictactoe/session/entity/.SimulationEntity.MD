# SimulationEntity

JPA entity mapping to the `session_db.simulations` table — the audit trail of `/simulate` run outcomes, one row per run. Unlike `SessionEntity`, this entity does carry outcome data (status, error info, timing) because that's exactly the audit record this table exists for; the live board/move-history during an in-progress run still lives only in the in-memory guarded store, never here.

## Key Components

- `@Entity` / `@Table(name = "simulations")` - Maps this class to the `simulations` table in `session_db`.
- `id` - `@Id` field; the primary key of this simulation run.
- `sessionId` - `@Column(name = "session_id", nullable = false)`; foreign key back to `SessionEntity`.
- `errorsCount` - `@Column(name = "errors_count", nullable = false)`; running count of recoverable errors encountered during the run.
- `startedAt` / `finishedAt` - `@Column` timestamps bracketing the run; `finishedAt` is nullable while the run is in progress.
- `status` - `@Column(name = "status", ...)` with `@Enumerated(EnumType.STRING)`; the shared `GameState` enum value the run finished (or is currently) in.
- `runningSessionId` - `@Column(name = "running_session_id")`; mirrors `sessionId` while `status` is `IN_PROGRESS`, null otherwise. The unique index `uq_simulation_running` on this column (see the V2 Flyway migration) is what actually enforces that a session can't have two concurrent simulations — the database itself rejects the second insert.
- `errorCode` / `errorMessage` - `@Column` fields populated when the run ends in `FAILED`, mirroring the service's standard error shape.
- Getter/setter pairs for every field above - Plain JavaBean accessors; this entity is mapped explicitly in the repository layer rather than leaking into service/domain code.

## Usage Example

```java
SimulationEntity run = new SimulationEntity();
run.setId(UUID.randomUUID());
run.setSessionId(sessionId);
run.setStatus(GameState.IN_PROGRESS);
run.setRunningSessionId(sessionId);
run.setStartedAt(Instant.now());
```

Inserting this row is what the unique index on `runningSessionId` uses to reject a second concurrent `/simulate` call for the same session with a database-level conflict, which the service layer translates into the 409 the API contract requires.
