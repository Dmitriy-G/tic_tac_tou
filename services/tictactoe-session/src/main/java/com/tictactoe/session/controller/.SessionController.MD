# SessionController

REST controller implementing the session lifecycle API exactly as specified in the project's API contract: create a session, start an asynchronous simulation, poll a session's state, and subscribe to its live SSE event stream. Holds no business logic itself — every method validates path/header input via Spring's binding and delegates immediately to `SessionService`, matching the project's "controllers hold no logic" convention.

## Key Components

- `@RestController` / `@RequestMapping("/sessions")` - Exposes this class's methods under the `/sessions` base path, matching the API contract verbatim (no `/api/v1` prefix).
- `@Tag(name = "Sessions", ...)` - OpenAPI/Swagger grouping metadata for the generated docs.
- `createSession()` - `POST /sessions` &rarr; 201; creates a new session and returns its initial `SessionResponse`.
- `simulate(String sessionId)` - `POST /sessions/{sessionId}/simulate` &rarr; 202; starts the session's automated game asynchronously, returning immediately while the simulation runs in the background.
- `getSession(String sessionId)` - `GET /sessions/{sessionId}` &rarr; 200; returns the session's current status, board, move history, and winner/error, used both for polling and for rehydrating the UI on page refresh.
- `events(String sessionId, String lastEventId)` - `GET /sessions/{sessionId}/events` &rarr; SSE stream (`text/event-stream`); disables proxy buffering (`X-Accel-Buffering: no`) and caching, and supports the `Last-Event-ID` header so a reconnecting/late subscriber gets the backlog of missed events before live ones.

## Usage Example

```http
POST /sessions
POST /sessions/{sessionId}/simulate
GET  /sessions/{sessionId}/events
Accept: text/event-stream
```

A client creates a session, kicks off the automated simulation, then opens the SSE stream to receive live board updates and the final win/draw/failure outcome as `SessionEvent`s.
