# SimulationStateWriter

Persists a simulation's progress and terminal outcomes to `session_db.simulations`, keeping the `SimulationEntity` audit row in sync with `SimulationProgress` after every step, and guaranteeing a terminal status even in loop-exit and failure edge cases.

## Key Components

- `@Component` - Registers the class as a Spring bean.
- `SimulationStateWriter(SimulationJpaRepository simulationRepository)` - Constructor injection of the repository.
- `persist(String simulationId, SimulationProgress progress)` - Writes the current error count and `GameState` to the entity after each step; sets `finishedAt` (and clears `runningSessionId`) only once the state is no longer `IN_PROGRESS`.
- `persistTerminal(String simulationId, SimulationProgress progress)` - Closes the loop-exit hole: if `SimulationRunner`'s loop stopped because it exhausted its move budget without the engine ever returning a terminal state, this forces a `FAILED` row via `fail`. A no-op when `progress` is already terminal, which is the normal case since the last `persist` call already wrote it.
- `fail(String simulationId, ErrorCode errorCode, String message)` - Persists a terminal `FAILED` outcome with the given error code/message. Swallows its own `RuntimeException` (logs and returns) so a failure to record a failure can never mask the original exception `SimulationRunner` is already handling.
- `findOrThrow(String simulationId)` - Private lookup that throws `InternalException` if the simulation row has vanished mid-run — a defensive guard against an impossible-but-not-quite-impossible state.

## Usage Example

```java
stateWriter.persist(simulationId, progress);
...
stateWriter.persistTerminal(simulationId, progress);
```

Called once per loop iteration and once after the loop exits in `SimulationRunner.run`, ensuring the `simulations` table always ends with a terminal row regardless of how the loop finished.
