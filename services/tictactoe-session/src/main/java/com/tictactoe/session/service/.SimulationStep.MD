# SimulationStep

Executes a single move within a simulation run: resolves the right `MoveStrategy` for the symbol whose turn it is, asks it for a position, sends the move to the engine, publishes the result, updates the run's progress, and returns a `MoveRecord` describing the attempt.

## Key Components

- `@Component` - Registers the class as a Spring bean.
- `SimulationStep(GameEngineClient, MoveStrategyResolver, SimulationEventPublisher)` - Constructor injection of the engine client, the per-symbol strategy resolver, and the event publisher.
- `execute(String sessionId, SimulationProgress progress)` - `sessionId` is the engine's `gameId` — one session is one game, so no separate simulation id is threaded through anymore. Determines the current symbol from `progress.currentSymbol()`, resolves its `MoveStrategy` via `MoveStrategyResolver`, selects a position, calls `gameEngineClient.move(sessionId, ...)`, publishes the move event, logs it at INFO with move number/symbol/position/status (per the Observability requirement in the root CLAUDE.md), calls `progress.recordStep(response)` to advance the run state, and returns a `MoveRecord(moveNumber, symbol, position, stepStatus)` built from the pre-advance move number.

## Usage Example

```java
while (progress.hasNextIteration()) {
    MoveRecord move = step.execute(sessionId, progress);
    stateWriter.recordMove(sessionId, progress, move);
}
```

`SimulationRunner`'s main loop calls `execute` once per iteration; each call is one full move —
select, send to the engine, publish, log, record — and hands the returned `MoveRecord` to
`SessionStateWriter` to persist.
