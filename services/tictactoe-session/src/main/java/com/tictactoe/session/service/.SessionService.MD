# SessionService

Top-level service backing the session controller's REST surface (create, read, subscribe). Coordinates `session_db.sessions`/`session_db.session_moves` persistence, simulation kickoff via `SimulationStarter`, and SSE subscription via `SseEmitterRegistry` — without ever holding its own copy of the board outside the database.

## Key Components

- `@Service` - Registers the class as a Spring-managed service bean.
- `SessionService(...)` - Constructor injection of `SessionJpaRepository`, `SessionMoveJpaRepository`, `SseEmitterRegistry`, `SimulationStarter`, and `OwnerTokenService` — no field injection, no `SessionStateStore` (deleted).
- `createSession()` - Generates a new `sessionId` (UUID), persists a `SessionEntity` row with `status = CREATED` and an empty board, and returns the initial `SessionResponse` built directly (a fresh session's shape is always the same, so no extra read-back is needed).
- `simulate(String sessionId, String ownerToken)` - Parses `sessionId` via `SessionIdUtils.toUuid` (400 `INVALID_SESSION_ID` on a malformed id, mirroring the engine's `GameStore.toUuid`), checks the session exists and the caller's token matches its owner (`NotSessionOwnerException` otherwise), then delegates to `SimulationStarter.start`, which validates further and kicks off the async simulation loop.
- `getSession(String sessionId)` - Rebuilds the full session view (status, board, moves, winner, error) from `session_db` via `toResponse` — the same source GET and SSE both effectively read from, so a page refresh, a lost stream, or a process restart can always fall back to this. This is the change that makes `GET /sessions/{id}` survive a restart: nothing here is in-memory anymore.
- `subscribe(String sessionId, String lastEventId)` - Validates the session exists, then registers an SSE emitter via `SseEmitterRegistry`, replaying any backlog after `lastEventId`.
- `toResponse(String sessionId, String ownerToken)` - Private mapper: loads the `SessionEntity`, loads its `SessionMoveEntity` rows via `SessionMoveJpaRepository.findBySessionIdOrderByMoveNumber` and maps them through `SessionMoveMapper`, and assembles the `SessionResponse` DTO.

## Usage Example

```java
SessionResponse created = sessionService.createSession();
sessionService.simulate(created.sessionId());
SessionResponse current = sessionService.getSession(created.sessionId());
```

Mirrors the typical client flow: create a session, kick off the automated simulation, then poll or
subscribe for progress — and `getSession` works identically whether the process serving it is the
one that ran the simulation or a fresh one after a restart.
