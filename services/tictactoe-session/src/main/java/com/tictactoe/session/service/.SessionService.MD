# SessionService

Top-level service backing the session controller's REST surface (create, read, subscribe). Coordinates the `session_db.sessions` persistence, the live in-memory state in `SessionStateStore`, simulation kickoff via `SimulationStarter`, and SSE subscription via `SseEmitterRegistry` — without ever holding its own copy of the board.

## Key Components

- `@Service` - Registers the class as a Spring-managed service bean.
- `SessionService(...)` - Constructor injection of `SessionJpaRepository`, `SseEmitterRegistry`, `SimulationStarter`, and `SessionStateStore` — no field injection.
- `createSession()` - Generates a new `sessionId` (UUID), persists the anchor row, initializes live state in `SessionStateStore`, and returns the initial `SessionResponse`.
- `simulate(String sessionId)` - Delegates to `SimulationStarter.start`, which validates and kicks off the async simulation loop.
- `getSession(String sessionId)` - Validates the session exists, then rebuilds the full session view (status, board, moves, winner, error) from `SessionStateStore` — the same source GET and SSE both read from, so a page refresh or lost stream can always fall back to this.
- `subscribe(String sessionId, String lastEventId)` - Validates the session exists, then registers an SSE emitter via `SseEmitterRegistry`, replaying any backlog after `lastEventId`.
- `toResponse(String sessionId)` - Private mapper from `SessionStateStore.LiveState` to the `SessionResponse` DTO.

## Usage Example

```java
SessionResponse created = sessionService.createSession();
sessionService.simulate(created.sessionId());
SessionResponse current = sessionService.getSession(created.sessionId());
```

Mirrors the typical client flow: create a session, kick off the automated simulation, then poll or subscribe for progress.
